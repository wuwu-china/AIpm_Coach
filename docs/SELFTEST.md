# AIPMCoach 自测清单（边界条件 / 兜底）

> 用法：在本地 `npm run dev` 后按顺序操作。标注 **【需配 Key】** 的项需要先在「AI 设置」里填入你自己的 Key；标注 **【调试开关】** 的项用浏览器控制台（F12 → Console）临时设置，测完执行给出的“恢复”命令。
>
> 说明：当前版本**没有情景题（主观作答题/评分页）**，相关条目统一标注 **N/A（本版本不适用）**，功能上线后再补测。

---

## 一、核心 edge case

### 1. AI 接口失败：重试 + 降级，不出空白页
**【需配 Key】**
1. 打开「AI 设置」，故意填一个**错误的 Key**，保存。
2. 完成一次测评进入结果页，等最弱维度的诊断自动生成（或手动展开任一维度诊断、点开「查看推荐资源」）。
3. 打开 Network 面板观察：失败后约 **1 秒**自动第 2 次请求、再失败约 **3 秒**后第 3 次。
- **预期**：3 次都失败后，诊断卡片显示预置通用诊断，右上角有很小的灰色「基础诊断」字样；资源区显示“资源暂时生成失败，请稍后重试 + 重试”。**任何情况下不出现空白卡片、报错页或一直转圈。**
4. 恢复：在「AI 设置」填回正确 Key（或清空 Key，此时直接用「基础诊断」，不发请求）。

### 2. 题库为空 / 某维度题量不足：禁止启动
**【调试开关】**
1. 控制台执行：`localStorage.setItem('aipmcoach.debug','bank_empty')`，刷新。
2. 进入介绍页 `/intro`；并直接访问 `/quiz`。
- **预期**：介绍页不显示「开始」按钮，出现橙色提示 **“题库未就绪，请联系管理员”**，并说明题量情况；直接访问答题页也显示同样的拦截页，无法进入题目。
3. 恢复：`localStorage.removeItem('aipmcoach.debug')`，刷新。
- **正常数据复核**：恢复后介绍页正常显示「开始」，可进入答题。

### 3. 中途关闭浏览器：进度保存 + 恢复卡片
1. 新开测评，答 3–5 题后**直接关闭标签页/浏览器**（不要点完）。
2. 重新打开网站首页 `/`。
- **预期**：首页出现醒目的描边卡片 **“你有一次未完成的测评，继续作答？”**，显示“已答 X/21 题”，有「继续作答」和「放弃重来」两个按钮。
3. 点「继续作答」→ 回到答题页，**停在刚才未答的那一道新题，已答题数不丢失**（顶部进度与 X 一致）。
4. 再次制造中途退出，回首页点「放弃重来」→ 旧进度清除，进入介绍页可重新开始；此时首页不再出现恢复卡片。
- 补充：答题页内直接按 F5 刷新也会原地续测（每题作答后立即写入 localStorage）。

### 4. 雷达图无数据：空状态引导
**【调试开关】**
1. 控制台执行 `localStorage.clear()` 清空本机数据。
2. 直接访问 `/result`。
- **预期**：**不渲染空白雷达图**，而是显示空状态：“完成测评后查看你的能力雷达图”，并有一个「开始测评」按钮，点击进入介绍页。
3. 正常完成一次测评后再进 `/result`，雷达图正常显示。

### 5. 情景题超长内容（2000 字限制 / 1800 字提示 / 超限截断）
**N/A（本版本不适用）**——当前产品只有标准化单选题，没有主观作答输入框。情景题上线后按：1800 字提示“还可以写 X 字”、2000 字强制截断并提示。

### 6. 情景题极短 / 空白提交拦截
**N/A（本版本不适用）**——同上，无主观题提交入口。

### 7. 快速重复点击“提交”
- **单选题（本版本实测项）**：答题时快速连点「下一题 / 查看结果」或某个选项。
  - **预期**：点击后按钮立即变灰显示 **“提交中…”**，约 0.25 秒内忽略后续点击；进度**每次只前进 1 题**，不会跳题、不会重复计分、控制台不报错；「跳过本题」在提交期间同样禁用。
- **AI 按钮**：连续快速点击「展开查看诊断」「查看推荐资源」。
  - **预期**：loading 期间按钮禁用/不重复发请求，只产生一次 AI 调用。
- **情景题“提交中…”防连点**：**N/A（本版本不适用）**。

### 8. 某维度只答了 1–2 题：不硬诊断
**【调试开关】**
1. 完成一次测评后进入结果页，控制台执行（以“数据与评估”为例）：
   `localStorage.setItem('aipmcoach.debug_insufficient','data_eval')`，刷新。
2. 展开“数据与评估”维度卡片。
- **预期**：卡片显示 **“答题数据不足，无法生成针对性诊断。建议你做一次专项测评。”**，**不调用 AI、不硬生成诊断**。
3. 恢复：`localStorage.removeItem('aipmcoach.debug_insufficient')`，刷新。
- 说明：正常 CAT 流程保证每个维度至少 3 题，该兜底用于异常/未来提前终止场景。六个维度 id 依次为：`ai_basics / llm_tech / ai_product / data_eval / ai_ethics / ai_business`。

## 二、AI 失控时的产品级响应

### 9. 情景题评分依据（分项打分展示）
**N/A（本版本不适用）**——没有情景题与评分页。上线后需展示每个评分标准的得分（如 √思路清晰度 18/20、×实操可执行性 5/20）。

### 10. 「我觉得评分不准」申诉
**N/A（本版本不适用）**——申诉对象（情景题评分）不存在。上线后：评分下方按钮 → 弹框填写理由 → 写入 localStorage，并提示“你的反馈会用于改进评分模型”。

### 11. 诊断必须引用具体题号，缺失则警告并重新生成
**【需配 Key】**
1. 配置可用 Key，完成测评后展开诊断。
- **预期（正常情况）**：诊断的「证据」或「鼓励」里至少出现一个**真实题号**（形如“第3题”），题号来自你本次实际作答。
- **异常兜底（自动触发，无需手动造）**：若模型第一版没引用题号，界面会出现一条琥珀色小提示 **“AI 没有引用具体题号，正在重新生成…”**，系统带上下文自动重新生成一次；重新生成仍不合格，或网络失败，则显示带「基础诊断」角标的通用文本，**不出现空白**。
- 可在 Network 面板核对：未引用题号时会比平时多一轮请求。

### 12. 能力分数可解释（分数构成弹窗 + 重测该维度）
1. 在结果页右侧「六维得分」列表，**点击任意一个维度的分数或整行**。
- **预期**：弹出“分数构成”弹窗，包含：
  - 该维度作答题数、答对、答错/跳过三个数字，并注明其中高难度题（L4–L5）几道；
  - 计分方式说明：**初始分 50，每题按「新分 = 旧分 × 0.7 + 本题贡献 × 0.3」更新**，并列出各难度答对/答错的贡献分表；
  - 每道题的逐题计分过程（题号、难度、对错、贡献分、更新后分数）；
  - 底部「重测这个维度」按钮。
2. 点「重测这个维度」→ 开始一套新的 21 题测评；打开控制台可见阶段一保底六维后，**阶段二加测优先该维度**（日志 `[CAT] 阶段二·维度专项：加测优先 xxx`）。
3. 从首页「查看我的成长报告」进入（历史快照模式）再打开弹窗：逐题过程显示为“历史快照未保存逐题记录”，但聚合统计与重测按钮仍可用。

## 三、主动规避项（确认产品里没有这些东西）

### 13. 检查是否存在游戏化/强制日活功能
逐项在首页、介绍页、答题页、结果页、成长报告里确认：
- [ ] 没有「连续打卡 X 天」展示；
- [ ] 没有「积分 / 积分商城」；
- [ ] 没有「PK / 排行榜 / 排名」；
- [ ] 没有“每天必须来”的强制激励或断签惩罚。

**预期：以上均不存在。** 结果页的「立即复测」仅按距上次天数给出**可选**建议（<3 天弱化、3–14 天常规、>14 天高亮），不打卡、不惩罚、不强制。
> 代码库已全局检索确认无上述功能；题库正文里出现的“排名/排行榜/积分”等字样只是**题目内容**，不是产品功能。

## 四、回归测试（改动后顺手过一遍）

1. 完整答完 21 题 → 雷达图、总分、等级正常；最弱维度诊断自动生成。
2. 再完成一次复测 → 叠加雷达（本次主色实线+半透明填充 / 上次灰色虚线）、三个关键数字、结果横幅（提升/突破/回落/稳定之一）正常。
3. 累计 ≥3 次快照 → 「查看完整成长曲线」可打开，六条维度线 + 总分虚线正常。
4. 「查看本次错题」弹窗：错项橙色“你的选择”、正项绿色“正确答案”、考察点齐全。
5. 「查看推荐资源」：每条资源无任何 URL，底部按钮为 Google 搜索词，点击新标签打开 Google 搜索结果页。
6. 命令行：`npm run test:cat` 全部通过；`npm run build` 无类型错误、构建成功。
