# 题库更新与版本发布手册（维护者必读）

题库真源是 **`data/bank.md`**（Markdown），前端使用的 `src/data/questions.ts` 是由脚本**自动生成**的，不要手改。
更新题库 = 改 `bank.md` → 本地重新生成并自测 → 提交 push → Vercel 自动发版。

---

## 一、一次完整更新的标准流程

```bash
# 0. 先拉最新代码，避免覆盖别人/自己之前的改动
git checkout main
git pull

# 1. 编辑 data/bank.md（新增题目追加到文件末尾，格式见第二节）

# 2. 由 MD 重新生成题库 TS，并核对控制台统计
npm run build:bank

# 3. 跑 CAT 不变量测试 + 类型检查/构建
npm run test:cat
npm run build

# 4. 更新版本信息（见第四节），然后提交
git add data/bank.md src/data/questions.ts src/data/content.ts CHANGELOG.md package.json
git commit -m "chore(bank): 题库更新至 xxx 题"
git push
```

push 后 Vercel 会**自动重新构建并部署**，通常 1–2 分钟线上即新版（无需手动操作）。

### `npm run build:bank` 必须确认的输出

- `结构异常数: 0`
- `未知标签: 无`（出现未知标签说明用了映射表里没有的标签，见第三节）
- 六个维度的题量与难度分布合理：每个维度在 **L3 附近要有足够题量**，否则自适应抽题会频繁跨难度兜底；`ai_ethics`（伦理）题量本来就少，新增时优先补它。

## 二、新增题目的标准块格式

在 `data/bank.md` **末尾追加**，题号（`###` 后的数字）顺延，**只用更大的新数字、绝不复用、绝不重新编号**（题号 gid 会被历史测评记录引用）。

```markdown
### 299、用一句话写清这道面试题的标题

**【题目类型】** 模型选型 / 模型评测 / 数据工程与评测集
**【难度】** 3

**【选择题】** 这里写题干（给出情境和问题，以问号结尾）？

A. 选项一的完整表述。
B. 选项二的完整表述。
C. 选项三的完整表述。
D. 选项四的完整表述。

**正确答案：** C

**【考核点】** 考察点一；考察点二；考察点三
```

> 题库只保留「题目类型 / 难度 / 选择题 / 正确答案 / 考核点」这些构建必需字段；解析、难点、关键词等说明性文字不进 `bank.md`（构建脚本也不读取它们），请在你自己的资料里另行留存。

硬性要求（否则会破坏测评公平性与解析）：

1. 恰好 4 个选项 `A.`–`D.`，唯一正确答案，`**正确答案：** X`。
2. **四个选项长度、详细程度要接近**——正确项不能系统性地最长/最详细，否则答题者会“看字多选哪个”；句末标点统一。
3. 难度 1–5：常识/定义 1–2；常规应用 3；多约束、全链路、需量化判断 4–5。
4. `【题目类型】` 只能用第三节标签表里的标签，多个用 ` / ` 分隔；**维度取按书写顺序第一个能映射的标签**，所以把最能代表该维度的标签放最前。
5. `【考核点】` 必填，AI 诊断会引用它；用分号分隔多个考察点。

> 删除过时/错误/矛盾题目：直接从 `bank.md` 删掉对应题块即可，**不要把后面的题重新编号**；在 CHANGELOG 的 Removed 里记下被删的 gid。老用户浏览器里的历史记录引用旧 gid 不会报错（代码做了容错）。

## 三、标签 → 六维度映射表

| 维度 | 可用标签 |
|---|---|
| **AI基础认知** | 大模型基础认知、机器学习基础、Prompt工程、多轮对话与记忆、意图识别与槽位、上下文工程、多模态 |
| **大模型技术理解** | 模型选型、模型微调与训练、合成数据、搜索推荐系统、性能与成本工程、RAG与知识库 |
| **AI产品设计** | AI产品设计、Agent与工作流编排、工具调用与MCP·A2A、badcase闭环迭代、产品方法论、需求分析与管理、0—1产品规划、产品版本规划、用户研究与画像、项目经验与复盘 |
| **数据与评估** | 数据工程与评测集、模型评测、数据分析与指标体系 |
| **AI伦理与风险** | 合规安全与伦理 |
| **AI商业化与落地** | 商业化与ROI、增长与运营、行业认知与趋势、项目管理与跨团队协同 |

以下为**纯软素质标签**：当一道题的标签**全部**属于它们时，该题不入测评池（仍可保留在 MD 里）：
职业规划与自我认知、职场沟通与软素质、HR面与通用素质、薪酬谈判、团队管理。

如果确实需要引入一个**全新标签**：先在 `scripts/build-questions.mjs` 的 `DIMENSIONS`（或 `SOFT_TAGS`）里登记它属于哪个维度，再跑构建；否则脚本会报 `未知标签` 且该题无法映射维度。

## 四、版本号与变更记录

两处版本要一起更新：

1. `src/data/content.ts` 的 `BANK_VERSION`：建议用 `年.月-题量`，例如 `2026.10-302`。它会写进每次测评会话，便于追溯某次结果用的是哪版题库。
2. `package.json` 的 `version`：遵循语义化版本——
   - 改错别字/修个别题：修订号 `1.0.1`
   - 新增/删除题目、小功能：次版本 `1.1.0`
   - 计分/维度等大改：主版本 `2.0.0`
3. 在 `CHANGELOG.md` 顶部按模板写 Added / Changed / Fixed / Removed，并注明题库规模变化。

发一个正式 tag（可选，便于回溯）：

```bash
git tag -a v1.1.0 -m "题库 285→302"
git push origin v1.1.0
```

## 五、推荐用分支 + 预览，避免错误题目直接上线

```bash
git checkout -b bank/2026-10-update
# 改题库、生成、自测、提交、push
git push -u origin bank/2026-10-update
```

在 Vercel 上每个分支会自动生成一个**预览地址**，先在预览地址完整答一遍确认无误，再在 GitHub 上发 Pull Request 合并到 `main`（合并即生产发版）。
万一上线后发现问题，可在 Vercel 控制台对 `main` 的历史部署一键 **Rollback** 回上一版。

## 六、不想手工清洗时

新题如果是 Word、表格、聊天记录等杂格式，或需要去重、纠错、选项等长改写，可以把原始材料交给 AI 按本手册的格式与校验规则批量生成草稿，你只需**人工终审答案是否正确**（答案对错不要让 AI 自动拍板），再粘贴进 `bank.md` 走上面的流程。
